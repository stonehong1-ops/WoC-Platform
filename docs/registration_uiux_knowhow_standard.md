# 🌟 World of Community (WoC) 등록창 UIUX 통합 노하우 표준 가이드

본 문서는 World of Community (WoC) 글로벌 통합 커뮤니티 플랫폼의 모든 등록 및 수정 창(소셜, 라이브광장, 클래스, 이벤트, 그룹, 숙박, 대여, 중고거래 등)에 공통으로 적용되는 UI/UX 디자인 표준, 다국어화 규칙, 비동기 진행률 피드백, 도메인별 데이터 구조화 및 업무 SOP 노하우를 하나로 통합 정의한 단일 표준 가이드입니다.

---

## 1. 👑 UIUX 코어 개발 3대 원칙

1. **Zero Design Deviation (디자인 편차 0%)**
   - 디자이너가 구현한 기존 마크업의 계층 구조, 패딩, 마진, 둥글기(rounded), 그림자(shadow) 등 모든 시각 요소를 1픽셀의 오차도 없이 100% 보존합니다.
   - 불필요한 리팩토링이나 CSS 최적화를 배제하고 Stitch 디자인 시스템의 원본 시각 레이아웃을 엄격히 수호합니다.

2. **Strict Multi-Language Binding (엄격한 다국어 바인딩)**
   - 코드 내부에 번역되지 않은 한국어 또는 영어 날것의 텍스트 문자열 배치를 전면 금지합니다.
   - 모든 노출 문자열은 다국어 사전(`kr.ts` 및 `en.ts`)에 동시에 동기화 등록하며, UI 레이아웃에서는 반드시 `t()` 번역 함수를 통해서만 출력합니다.

3. **Progress % Feedback (실시간 백분율 진행도 피드백)**
   - 미디어 파일 업로드 등 비동기 처리 동안 사용자가 화면을 이탈하지 않도록 직관적인 0% ~ 100% 실시간 백분율 진행 상태를 제공합니다.
   - 사용자 피드백 영역은 등록 버튼 자체 내부의 텍스트 공간을 활용하여 UI 여백 훼손 없이 깔끔하게 출력합니다.

4. **Device Safe Area Protection (모바일 노치 및 디바이스 침범 0% 안전 규격)**
   - 아이폰 노치/상태바 및 안드로이드 하단 소프트키/홈 바 환경에서 최상단 헤더와 최하단 내비게이션 바가 겹치거나 잘리는 화면 침범을 전면 차단합니다.
   - 상단 헤더는 `paddingTop: 'env(safe-area-inset-top, 0px)'`, `height: 'calc(56px + env(safe-area-inset-top, 0px))'` 인라인 스타일 보정을 필수 적용하고, 헤더 바로 뒤에 동일 높이의 Spacer를 배치합니다.
   - 하단 푸터 바는 `paddingBottom: 'calc(16px + env(safe-area-inset-bottom, 0px))'`, `height: 'calc(76px + env(safe-area-inset-bottom, 0px))'` 패딩 보정을 고정 적용합니다.
   - 최상위 팝업/풀스크린 뷰어의 z-index는 `z-[100000]` 이상의 계층을 보장합니다.

5. **Draft Discard Confirmation Guard (작성 중 이탈 방지 확인 알림 필수 표출)**
   - 등록 및 수정 모달에서 사용자가 상단 화살표 버튼, 취소 버튼, 또는 디바이스 뒤로가기를 눌러 화면을 닫으려고 할 때, 입력 폼(사진, 타이틀, 본문, 가격 등)에 작성 중인 내용이 1개라도 존재하는 경우 반드시 다국어 확인 알림(`confirm(t('common.confirm_discard'))`)을 실행해야 합니다.
   - 사용자가 명시적으로 '확인'을 누른 경우에만 등록 모달을 완전 해제(`onClose()`)하며, '취소' 시 작성 중인 데이터 입력을 유지합니다.
   - 입력 데이터가 0개인 깨끗한 상태에서는 추가 확인 없이 지체 없이 모달을 닫습니다.

6. **Single History Navigation Control (URL 쿼리 및 뒤로가기 훅 이중 충돌 방지)**
   - URL Search Params 기반 모달(`?create=true` 등)과 `useBackButtonClose` 훅을 함께 사용할 때는 이중 `pushState` / `history.back()` 연쇄 호출로 인해 닫기가 막히고 화면이 깜빡이는 현상을 방지해야 합니다.
   - 헤더 화살표 클릭 시 direct state handler(`onClose`)를 단일 경로로 즉시 호출하고, `useBackButtonClose`는 최상위 뷰어 모달에서 단 1회만 단일 제어하도록 구현합니다.

## 2. 📱 등록창 단계별(Step-by-Step) 공통 UI 구조 스펙

모든 등록창은 정보 입력의 부담을 낮추고 무결성을 보장하기 위해 단계별 폼 구조로 제공합니다.

1. **상단 프로그레스 헤더 & 2단계(2-Step) 폼 표준**
   - 현재 단계 수치(Step 1 / 2 단계)와 해당 단계의 핵심 영역 명칭을 명확히 표시하며, 2단계 슬림화 구조를 기본 표준으로 적용합니다. (Step 1: 기본 정보·미디어·스토리 설명, Step 2: 가격·거래 장소·조건 및 저장)
   - 별도의 불필요한 프리뷰 요약 단계를 배제하여 등록 피로도를 최저 수준으로 낮춥니다.
   - 진행 바(Progress Bar)를 통해 전체 입력 작업의 위치를 시각적으로 전달합니다.

2. **인물·장소·클럽 공통 선택기 100% 디자인 통일 (핵심 원칙)**
   - 등록 과정 중 사람(강사, 오거나이저, 판매자), 장소(베뉴, 스튜디오, 직거래 위치), 클럽(그룹, 소사이어티)을 선택하는 바텀시트 및 팝업의 폰트 타이포그래피, Stitch 대표 시그니처 컬러, 서치 바, 체크 액션 버튼, 네비게이션 동선을 소셜 및 클래스 등록창과 100% 동일하게 완전히 일치시킵니다.
   - 우회용 텍스트 링크 버튼을 배제하고 카드를 직접 터치하여 모달을 여는 1-Click 터치 선택 동선을 적용합니다.

3. **카드 단위 정보 그루핑 & 레이블 타이포그래피 표준**
   - **카드 정보 그루핑**: 입력 폼 항목은 기능 단위로 둥근 카드 모듈(`border border-[#e0e4e5] rounded-2xl bg-white shadow-sm overflow-hidden`) 형태로 구조화하며, 카드 헤더는 은은한 회색 상단 바(`bg-[#f8f9fa] px-4 py-3 border-b border-[#e0e4e5]`)에 틴트 아이콘과 영역 타이틀(`text-[14px] font-bold text-[#007AFF]`)을 대칭 배치합니다.
   - **Form Label**: `text-[13px] font-bold text-slate-600 mb-1.5` 스펙과 필수 기입 필수 항목에 레드 아스테리스크(`<span className="text-red-500">*</span>`) 표기를 준수합니다.
   - **Form Field**: `bg-[#f8f9fa] border border-[#e0e4e5] rounded-xl px-4 py-3 text-[15px] font-medium focus:border-[#007AFF] focus:ring-1 focus:ring-[#007AFF] outline-none transition-all` 규격을 전 등록창 공통으로 동일 적용합니다.

4. **유효성 검사 기반 단계 이동 제어**
   - 각 단계별 필수 입력 항목(타이틀, 일정, 대표 장소 등)의 기입 여부를 실시간 검증합니다.
   - 미입력 시 '다음 단계' 및 저장 버튼 클릭 시 명확한 다국어 피드백 안내 모달을 띄워 데이터 무결성을 보장합니다.

5. **상단 헤더 우측 버튼 전면 금지 및 하단 고정 내비게이션 바 100% 전담 철칙**
   - 상단 헤더 우측 영역에는 '저장', '완료', '제출' 등 어떠한 동작/저장 액션 버튼도 배치하는 것을 전면 금지합니다.
   - 모든 단계 이동('이전 단계', '다음 단계')과 최종 저장/제출 동작은 반드시 **하단 고정 내비게이션 바(Fixed Bottom Navigation Bar)** 내에서만 100% 일관되게 처리합니다.
   - 상단 헤더 우측 영역은 대칭성 유지를 위해 빈 공간(`w-10`) 또는 단순 닫기 화살표만 제공합니다.

## 3. 🌐 다국어 사전 정의 및 문장 종결자 규칙

1. **다국어 사전 키 계층화**
   - 사전 키는 서비스 계층 도메인을 접두어로 시작하는 계층형 구조로 정의합니다. (예: `class.register.[key]`, `event.register.[key]`)
   - `kr.ts`와 `en.ts`에 동일한 키를 반드시 동시에 선언하여 영한 무결성을 맞춥니다.

2. **문장 종결자 규칙 (중요)**
   - 한국어 번역 텍스트와 라벨 끝에 콜론(`:`) 기호를 붙이는 것을 전면 금지합니다.
   - 모든 문장은 마침표(`.`), 물음표(`?`), 느낌표(`!`) 또는 기호가 없는 자연스러운 단어 형태로 종결합니다.

## 4. 📂 도메인별 데이터 구조화 및 업무 SOP 노하우

### 4.1 Class (클래스 등록)
- **일정 개요 (`schedule`)**: 단일 객체(`{}`) 구성을 강제합니다. (`recurrenceType`, `startDate`, `endDate`, `dayOfWeek`, `startTime`, `endTime`)
- **개별 세션 (`sessions`)**: 특강일 경우 개별 일정을 세션 배열(`[]`)로 분리 저장합니다.
- **하위 호환 필드**: 기존 예약 엔진과의 호환을 위해 역정규화 단일 가격 필드 `amount`, `price`, `dailyClassPrice`를 동일값으로 동시 생성합니다.
- **자율 실행 및 보고**: 데이터 가공 완료 후 별도 승인 대기 없이 저장 및 홍보 그룹 연동까지 자율 처리하고 일일 보고 양식에 맞춰 작성합니다.

### 4.2 Event (이벤트 및 축제 등록)
- **중복 억제 및 승계**: 기존 문서 검색 후 동일 이벤트 존재 시 신규 생성을 차단하고 포스터 및 일정 필드만 갱신(Merge)합니다.
- **선행 등록**: 개최 장소(`venues`)를 DB에 선 등록한 후 연동하며 주최자(`hostId`)는 실재 오거나이저 계정(자연인)으로 매핑합니다.
- **프로그램 분할**: 축제 기간 세부 강습과 밀롱가를 독립 프로그램 객체 배열(`programs[]`)로 배정합니다.
- **다차원 할인**: 얼리버드 및 복수 티켓 패키지 요금제를 입체 구조화합니다.

### 4.3 Social (소셜 및 밀롱가 등록)
- **정기 소셜 중복 금지**: 정기 소셜 문서를 중복 생성하지 않고 `djs[]` 배열에 일자와 DJ 정보만 추가 갱신합니다.
- **장소와 오거나이저 분리**: 기획 주최자 이름과 물리 베뉴 장소를 명확히 분리 매핑합니다.

## 5. ⛔ 타 영역 업무 요청 거부 및 전용 SOP 가동 프로토콜

1. **업무 권한 엄격 통제**
   - 각 에이전트는 자신에게 부여된 담당 업무 영역(예: Class 담당, Event 담당 등)만을 전담합니다.

2. **거부 및 알림 수순**
   - 타 영역 요청 유입 시 즉시 작업을 거부하고 스톤님께 알립니다.
   - 해당 영역의 전용 SOP 가이드라인 제공을 요청합니다.

## 6. 🔍 9대 등록창 수평 확장 점검표 및 자가 검증

1. **대상 등록창**: 대여(Rental), 숙박(Stay), 상점(Shop), 중고거래(Resale), 그룹강좌(Group Class), 그룹숙박(Group Stay), 그룹캘린더(Group Calendar), 프로필등록(People), 라이브개설(Live).
2. **배포 전 필수 자가 검증**:
   - 원본 HTML 대비 픽셀 편차 0% 부합 여부.
   - `kr.ts` 및 `en.ts` 영한 무결성 100% 매핑 및 문장 끝 콜론 기호 완전 제거 확인.
   - 실시간 다국어 동적 치환 작동 여부.
   - 파일 업로드 시 버튼 내 실시간 0% ~ 100% 카운트업 진행률 노출 확인.
